## Хронология тестирования: старый граф → баг → фикс → новый

1. **Попытка №1 — WARN «карта не загружена».** Причина найдена по исходникам:
   глобальное имя `map` — таблица API модуля, а `nodes` — приватная переменная
   модуля (`map.lua:25`); `map.nodes == nil` ВСЕГДА, узлы — через

   гварды; `map.load()` — только при пустых nodes; `build_serial` в meta — после
   возможного `map.load()`.
2. **Тест 2.7 — экспорт прошёл, но чекер поймал БАГ** (FAIL «isolated, но есть
   ребро» + WARN `phantom == -E`): см. ключевую находку ниже.
3. **Фикс + повторный экспорт** — граф «перевернулся» (см. таблицу до/после),

4. **example:** срез «первые 20 по id» давал 45 ссылок наружу → вариант (a):

## Ключевая находка: links в навиграфе хранятся ОДНОСТОРОННЕ

**Симптомы (старый граф):** 5098 «dead_end» из 5439 узлов, 91.1% рёбер без
`radius_m`, FAIL «isolated-узел участвует в ребре», `phantom == -E` ровно.

**Причина:** цепочки next от DecalRoad пишут `A.links[B]`, а обратного
`B.links[A]` может не быть. Доказательство — арифметика: сумма `|links|` по всем
узлам равна числу рёбер ровно ⇒ каждое ребро лежит ровно в одном `links`.
Мой `degree = |links|` был НЕ неориентированной степенью: цепочка A→B→C давала
три «dead_end», «приёмники» считались isolated, `degree==2` почти не
встречался ⇒ `radius` почти не считался.

**Фикс (`68d5a09`):** проход A — сбор всех рёбер + union-смежность (O(E));
`degree` = |union-соседей| (`A.links[B]` ИЛИ `B.links[A]`); radius/angle/типы —
от правильного degree; порядок рёбер детерминирован (сортировка по edge_id).

## Проверка плоскости (x/y/z) — direction_deg КОРРЕКТЕН, бага нет

Размахи по осям всех 5439 узлов: **x = 2373 м, y = 1940 м, z = 98 м**
(z ∈ [3.8, 101.7]). ⇒ **z — вертикаль (высота), x-y — горизонтальная плоскость**
(топ-вью, z-up — как в самом BeamNG).

Сверка `direction_deg` на всех 5656 рёбрах: с формулой `atan2(dx, dy)` (плоскость
x-y) — **0 расхождений**; с `atan2(dx, dz)` (x-z) — 5573 расхождения.
**Вывод: азимут считается в правильной плоскости** (0° = север +Y, по часовой),
схема корректна. Фикс не нужен.

## Известные ограничения (НЕ чинить сейчас, зафиксировано)

1. **Выбросы `radius_m` > 1000 м:** 100 рёбер, максимум 74018.5 м — артефакт
   формулы трёх точек на почти-коллинеарных точках (знаменатель 4S близок к
   нулю, радиус «улетает»). Для Фазы 4 не критично: `recommended = min(limit, phys)`,
   физическая скорость `3.6·sqrt(μ·g·R)` растёт с R и на прямых превышает лимит
   дороги, так что минимум отсекает выброс. **Если понадобится — в Фазе 4
   добавим кап: `if radius_m > 10000 then radius_m = null`.**
2. **isolated-узел:** 1 шт (x=1401, y=−88, до ближайшего обычного узла 492.7 м) —
   отрезанный кусок дороги за игровой зоной. Нормально.
3. **Связность:** 12 компонент, наибольшая 5199 (95.6%) — норм для навиграфа
   BeamNG (остальные — отрезанные дорожки).
