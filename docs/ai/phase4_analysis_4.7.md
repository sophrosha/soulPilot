## Разбор FAIL 5ж (B) — аномалия первого кадра, НЕ steady-state

Кадр t=22.063: `steer_smoothed = +0.1922` при `steer_raw = 0.0000`, далее спад 0.192→0
за 0.52 c (к t=22.63 dev=0). Это НЕ «конвейер не дотягивает» — это **включение модуля**:

- `apl_wheel("on")` исполнен на sim t≈2 (wall 13:28:05, машина на спавне, speed≈0),
  но `ai.isDriving` стал true только на t≈22.06 (первое движение: speed 0.0003 → 0.05).
- В первый кадр движения raw дал **импульс ~0.192 на 1-2 кадра** (input.state.steering).
  CSV пишет каждые ~3.2 кадра (5382 строки/288.7 c при 60 fps) — **этот кадр в CSV не попал**;
  в записанной строке t=22.063 виден только его результат: sync `pipe := 0.192`.
- Дальше raw=0 → конвейер спокойно возвращает руль к 0 за 0.52 c (ema 0.06 + lerp 0.08).
- Физически: руль щёлкнул ~19% упора на старте движения и плавно вернулся; speed≈0.05 м/с —
  игрок НЕ мог это почувствовать (и не пожаловался).

**Вывод:** 5ж-FAIL = 10-строчный transient ВКЛЮЧЕНИЯ на стоянке, к езде/срезанию углов отношения
не имеет. В установившемся режиме оба прогона чисты. Статус: **микро-аномалия первого кадра,
не блокер; проверить повторяемость в 4.8** (если повторится — микро-фикс первого кадра отдельно).

## Fix 5b (У3) — прыжок руля при apl_wheel("on") в движении: НЕ ПОДТВЕРЖДЁН

Все интересные кадры в данных (wall↔sim поправка −7 c). **Реальных OFF/ON в A — одна пара
(wall 13:22:42 off → 13:23:11 on, sim 207/236); в B — вообще нет.** «Gap» между
engaged-сегментами чекера — это моменты, когда sm ТОЧНО сошёлся с raw (снап), а НЕ
выключение модуля: доказательство — на t=114.24 sync НЕ произошёл (sm стартовал с 0,
а не с −0.168), значит needInit был false и ai.isDriving не прерывался:

(граница поискового окна — onset мог быть и раньше), к виражу скорость уже сброшена

(50+ км/ч) невозможно — таких поворотов в прогонах не было. Интеграционный тест
